# Refmon

Refmon detects, contains and explains attacks on endpoints and servers by judging **behaviour**, not
signatures. It does not try to recognise an exploit, a lure or a malware family. After an attack
succeeds the attacker still has to act (run code, write files, connect out, read secrets, persist),
and those actions break the role of the process that was exploited. Refmon watches for that
consequence, so it is meant to catch attack types that do not exist yet.

For every *story* of related events it asks three questions:

| Question | Fails when |
|---|---|
| **Origin** | the triggering input came from outside the trust boundary (web, mail, removable media, an inbound request, a downloaded package, agent input) |
| **Contract** | a process does something outside its role: a web worker starting a shell, an interactive shell running a pasted command, any process tampering with security tools, changing many files, fanning out, or launching an unsigned external file |
| **Effect** | it tries a dangerous action: fetch, hide, persist, escalate, lateral movement, exfiltration, tamper, credential or protected-asset access, mass change |

Three failed questions are a block, two a hold (ask the user, or pause and quarantine pending an
admin), fewer an allow. Underneath, an *evidence calculus* turns the signals into log-likelihood
ratios with cost-based thresholds, so the verdict states its contributions in nats and the classic
3/2/1 count stays as the human-readable explanation and the fallback. Overrides are absolute: a
canary read, a labeled process touching a protected asset, tampering with Refmon itself.

Privacy is a design constraint, not a feature: content (commands, URLs, bodies) is replaced by
per-device HMAC fingerprints in the first stage, raw events live in memory for at most ten minutes,
and only verdicts under pseudonyms leave a device. There is no machine learning, only deterministic
rules and counted baselines, and everything is testable by replaying JSON Lines event files.

**Status.** Replay-only research code. Nothing here runs on a real sensor; no real malware, exploit
or personal data is in the repository (everything is a harmless, self-made stand-in; see
[docs/phase-8-plan.md](docs/phase-8-plan.md) for what a real platform needs). The results are in
[docs/results.md](docs/results.md) and every table in it is regenerated by one command.

## Install

Python 3.12 or newer.

```bash
make install            # python3 -m venv .venv && pip install -e ".[dev]"
```

or, without make: `python3 -m venv .venv && .venv/bin/pip install -e ".[dev]"`. The package needs
`pydantic`, `pyyaml` and `cryptography`; the tests also need `pytest`, `hypothesis` and `ruff`.

## Run the tests

```bash
make test               # .venv/bin/pytest -q
make all                # lint, tests, privacy audit, robustness matrix, publishability check
```

The suite is about sixteen hundred tests (unit tests per rule, contract, effect and override;
property tests with Hypothesis; replay of every golden scenario; the privacy audit; the self-test)
and takes under a minute.

## Reproduce every result

```bash
make reproduce          # .venv/bin/python scripts/reproduce.py
```

This generates the variants of the active seed once, extracts the tags `v1.0` to `v1.3` from git,
replays the same file in each, compares the four, checks the outcome against the committed
per-variant data in `docs/evaluation/`, runs the golden catalog in every version, builds the
coverage map, runs the privacy audit, the publishability check and the test suite, and rewrites the
generated blocks of [docs/results.md](docs/results.md). It needs the git tags (`git fetch --tags`)
and no network. A run takes a few minutes.

## Layout

| Path | What |
|---|---|
| `src/refmon/` | the pipeline: `pipeline/` (Observe, Tag, Link, Judge), `calculus/` (the evidence calculus), `gate.py` and `contain.py` (act), `exposure.py`, `selftest.py`, `heartbeat.py`, `report.py`, `variants.py` (the robustness generator) |
| `tests/` | unit, property and replay tests; `tests/golden/` has the 46 scenarios (`Sxx.events.jsonl`, `Sxx.expected.json`) |
| `scripts/` | `reproduce.py`, `generate_variants.py`, `dump_matrix.py`, `compare_versions.py`, `check_publishable.py` |
| `docs/` | `results.md` (final tables), `design-decisions.md` (A1 to A58), `progress.md`, `review-list.md`, `variant-seeds.md`, one `v1.x-evaluation.md` per version, `phase-8-plan.md` |
| `CLAUDE.md` | the specification (written as a prompt file for the coding agent that built the project): architecture, the catalog, the evidence calculus (C11), the coverage map (C13). Tests read the weights and the coverage map from it |

Command line: `refmon keygen | init-policy | sign | verify | learn | approve | apply`, and
`python -m refmon.audit tests/golden` for the privacy audit.

## Versions

`v1.0` is the state after Phase 7 and stays frozen; each later tag changes structural rules in
response to findings of the previous evaluation and is measured on a variant seed recorded before
the change ([docs/variant-seeds.md](docs/variant-seeds.md)). The golden event files are generated by
`python tests/golden_builder.py` (check with `--check`) and contain fingerprints of placeholder
labels only.
