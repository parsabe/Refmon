# v1.1 evaluation: v1.0 and v1.1 side by side on the new variant seed

Seed **268805905** (recorded in [variant-seeds.md](variant-seeds.md) before any v1.1 code was written). Both versions replayed the same 634 generated variants of the 27 malicious golden files; the event streams were hashed and are identical in the two runs. v1.0 is the tag `v1.0` (extracted, not rebuilt), v1.1 is the tag `v1.1`, and both were run by the same script ([scripts/dump_matrix.py](../scripts/dump_matrix.py)); the report is made by [scripts/compare_versions.py](../scripts/compare_versions.py). The raw per-variant results are in [docs/evaluation/](evaluation/).

## How to read the numbers

- **block**: the decision is block.
- **effective hold**: the decision is hold and the Gate paused or quarantined something (a `hold` or `quarantine_file` action was issued; counted from the actions of the replay, so a hold that later timed out still counts).
- **hold pauses nothing** (F1): the decision is hold and the Gate had nothing to pause. The user is asked, nothing is stopped.
- **uncontained** = allow + hold pauses nothing.
- **blocks that act on nothing**: a block with no action at all (a different case, see F6 below; they are counted as blocks, as asked).

Only the **seeded combinations** (12 per scenario) depend on the seed. The baselines, the no-label variants and the one-factor variants are the same events for every seed, and the Phase 7 matrix of v1.0 was where F1 to F4 were found, so they are a regression check and not fresh evidence. The two groups are reported apart.

One smoke run of the v1.1 code on a throwaway seed (`seed=1`) was made to check that the new matrix columns work; its numbers were not used and no code changed afterwards.

## The golden catalog

The 46 golden files give the same `decision` and `rule_decision` in v1.0 and v1.1, and the same failed questions, and `tests/` pass (1580 passed, 2 expected failures). What differs is the containment of five scenarios: S05 now pauses the shell that produced its signals (F1, the golden file declares it), and S32 to S35 are blocks that first passed through a hold on the launcher, which v1.1 now pauses (see F5).

## What is still allowed (7 of 634)

| variant | why |
|---|---|
| S05 combo-11 (popular_trusted, stripped flags) | a typed command with no label, to a destination the policy trusts, nothing hidden: G1 |
| S19 timing=minutes, combo-7, combo-10 | slow file changes: G2 |
| S19 timing=beyond_window, combo-11; S27 timing=beyond_window | one event per story: G3 |

The hour-scale window fires (the unit tests show 60 distinct file changes in an hour, and 5 oversized responses to one client in an hour, are significant), but the S19 stand-in changes 55 files and the S27 stand-in sends 3 oversized responses, so no spacing of them can reach those thresholds. A lower long-window baseline would catch them; it would also be fitted to these two stand-ins, so it is left to a pilot (A29, A49) and to a new seed.

## F5, found while evaluating (not fixed)

A hold that falls back to the signal producers (A47) can pause a process that is not part of the attack: the launcher (file manager, run dialog) that only started the command. When the story then becomes a block, the block is labeled-only, kills the labeled processes, and leaves that launcher paused. Measured on the same variants ([scripts/paused_after_block.py](../scripts/paused_after_block.py)): v1.0 left a process paused after 1 of 446 blocks; v1.1 leaves one after 64 of 487 blocks, 56 of the processes being launchers that never carried a label. A pause can be undone, but nothing undoes it by itself. Two fixes would remove it, either of which is a v1.2 and needs its own seed: release the fallback pauses that a block does not kill, or leave channel roles (`non_carrier_roles`) out of the fallback.

## F6, seen in the same data (not fixed)

A block on a story with no labeled process acts on nothing, because Contain is labeled-only and the fallback of A47 is for holds only. This is F1 for blocks: 11 of 446 blocks in v1.0 and 9 of 487 in v1.1 (the no-label variants of S17, S19 and S20, S08 with a typed command and S05/S02 entered through a web worker, where the canary or the Contract signals decide and no label exists). They are blocks in the decision and counted as blocks above; what they do to the host is nothing.
