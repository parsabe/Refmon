# v1.5 to v1.7 evaluation

Three rounds, each measured on a variant seed recorded before any of its code was written
(docs/variant-seeds.md), with the same variant file replayed in both versions
(`scripts/generate_variants.py` once, `scripts/dump_matrix.py` per version,
`scripts/compare_versions.py`). Per-variant data: `docs/evaluation/*-seed-833754500.jsonl` and
`*-seed-545728926.jsonl`; full comparisons: `docs/evaluation/comparison-seed-*.md`. The weights are
unchanged. Since the tags `v1.0` to `v1.3` are missing from this clone (docs/progress.md), each
"before" version is a copy of the source taken just before the round's first change.

"Contained" is block plus effective hold. From this evaluation on, a hold is effective when the
Gate paused, quarantined **or killed** something (F12: a hold that times out is denied and killed,
which contains at least as much as a pause); both columns of every table below use that measure.

## Round 1: v1.4 to v1.5, seed 833754500 (882 variants)

Changes (design-decisions.md): A60 lineage-aware trust of destination classes (F2), A61 incidents
end after an hour of silence (an operational fault: one contained story froze every baseline for
good), A62 bounded state for long-running pipelines (opt-in, off in replay).

| effective hold | 138 | 139 |

One variant changed: S18 combo-1 (trusted destination, timing beyond the window) from allow to
effective hold. Exact McNemar on the changed pairs (0, 1): p = 1.0, so the gain is real for that
variant but not statistically distinguishable from no change; it does not justify a claim of
improved detection in general.

Findings of round 1 (not fixed on this seed): **F11**, a block in a story that has an external
origin label but no labeled process acts on nothing, which is how a hold that times out ends when
the label sits on content only a channel role touched (S21 combo-5); **F12**, the measure above.

## Round 3: v1.6 to v1.7, seed 616687759 (878 variants)

Change: A64. External content hands *every* live label of its fingerprint to the process that
ingests it, as an exec already did (rule 3). Until v1.6 only the strongest was handed over, and
which one is strongest depends on the decay speed, so the half-life changed which stories events
linked into: a randomised property test (`tests/test_v13.py`, a faster-fading label must never make
a story stronger) found a counterexample. It holds again for 2000 random examples.

| | v1.6 | v1.7 |
|---|---:|---:|
| malicious contained (634) | 623 | **623 (98.3 %, [96.9, 99.0])** |
| seed-decided subset (323), contained | 312 | 312 (96.6 %, [94.0, 98.1]) |
| neutral benign (154): allow / hold / block | 128 / 23 / 3 | 128 / 23 / 3 |
| neutral false block rate | 1.9 % | 1.9 % [0.7, 5.6] |
| variants whose outcome changed | | none |

A64 is a correctness fix (the calculus is a function of the evidence, not of an accident of
ordering), not a detection change; no outcome moved. The three false blocks are S37 (a signed
installer from the software portal whose steps are further apart than the quiet window): finding
F10, left open on purpose, because carrying the trusted-root override across stories would widen an
absolute *allow* that a compromised signed updater could use.

## What is still not contained (v1.6, seed 545728926; the same classes on seed 616687759)

| | variants | finding | why |
|---|---:|---|---|
| slow mass change | 6 (S19) | F3, G2, G3 | changes 9 to 40 minutes apart stay under the benign rate baseline; only a baseline measured in a pilot can lower it without fitting it to the stand-in |
| trusted destination, no external lineage | 5 allowed (S07, S25) + 1 hold that pauses nothing (S12) | F2, G1 | the connecting process was started by a channel role or ran typed text, so it has no lineage for A60 to see; closing it means a trusted class excuses only roles whose contract lists it, a policy decision with a false-alarm cost |

Across the three seeds the pipeline contains 98 to 99 % of the generated attack variants with a neutral
false block rate of 0.6 to 1.9 %. These are variants of the project's own 46 scenarios replayed as event
files, not attacks on a real host; they say how robust the rules are to mutation, not how a
deployment would fare.

## The live command barrier (not part of the matrix)

`refmon guard` judges a command before it runs, from what the command text says it will do
(`src/refmon/intent.py`). Before this change, 13 of 17 attacker behaviours were allowed even when
pasted from the web (reverse shells, SSH-key and systemd persistence, history wiping, cloud and
cluster credential reads, preload injection, mass encryption, killing Refmon). Now each of 23
behaviours is refused when typed locally and blocked when pasted, and 23 benign look-alikes
(`ssh -i key`, `cat ~/.bashrc`, `crontab -l`, `rm -rf build/`, `LD_PRELOAD=libjemalloc.so`, ...)
stay allowed (`tests/test_intent.py`). That suite was written together with the analyser, so it is
coverage, not a robustness measurement; copying a whole project off the host with `scp` and deleting
named directories under the home directory stay allowed by choice, because they look like everyday
work on a cluster.
