# v2.0 evaluation

v2.0 was measured on variant seed **171139148**, drawn with `secrets.randbelow(900_000_000) +
100_000_000` and recorded in docs/variant-seeds.md before any v2.0 code was written. The variants
were generated once (`scripts/generate_variants.py`, 886 variants) and replayed in v1.7 (a copy of
the source taken before the first change) and in v2.0 (`scripts/dump_matrix.py`), then compared
(`scripts/compare_versions.py`). Per-variant data: `docs/evaluation/v1.7-seed-171139148.jsonl` and
`v2.0-seed-171139148.jsonl`. Full comparison: `docs/evaluation/comparison-seed-171139148.md`. The
weights are unchanged. "Contained" means block plus effective hold, where a kill counts (F12).

## Changes

- **A65, trust is lineage (F10).** A process that ingests content from a trusted root source
  carries a trust mark, and its children inherit it. The mark fades and dies exactly like a label.
  Until v1.7 trust belonged to one story, so a step of a signed install made further away than the
  story quiet window was judged as if nothing trusted had happened. An external label in the same
  position would still have counted. The mark is narrower than a label:
  - a channel role that ingests trusted content does not acquire it;
  - it never passes to files or persistence items;
  - any live external label in the lineage cancels it;
  - the overrides that block (canary, protected asset, tampering with Refmon) still come first.
- **A66, a channel role relays and does not act.** A fallback hold or block can reach a channel role
  that started a program in the story. When it does, it now acts on that program. Until v1.7 such a
  hold paused nothing. The channel role and the user's shell are still never touched.
- **A67, the live barrier** (not part of the matrix, below).

All 21 remaining holds are expected: S49 and S50 hold by design, and no benign variant ends worse
than its unmodified file. Five benign variants changed, all of them in v2.0's favour: S37 went from
block to allow twice, and S24 from hold to allow three times. All five are timing variants of a
trusted install. On the changed pairs (0, 5), the exact McNemar test gives p = 0.0625. That is
consistent with A65's purpose but not significant at 5 % on its own, because only five benign
variants carry the pattern. The labelled benign groups (variants whose mutation adds a Contract
violation or an Effect) did not change.

A66 had nothing to act on in this seed: v1.7 produced no hold that paused nothing. Its evidence is
therefore its unit tests (`tests/test_v20.py`) and the property test of `tests/test_contain.py`,
which found the first draft too wide.

## The live command barrier (A67)

The barrier judges a command from its text before running it (`src/refmon/intent.py`). v2.0 analyses
the text twice:
- as written;
- after undoing the shell's own word-hiding: empty quotes or a backslash inside a word, `${IFS}`,
  `$'\x..'` escapes, quotes around a single word, and variables assigned earlier on the line.

Hiding a word in one of these ways is itself the hide behaviour. The new behaviours are:
- fetched code run through process substitution;
- git hooks used as persistence;
- containers given host privileges;
- reverse and dynamic SSH tunnels;
- sending the home directory or the root to a host (exfil).

| probe set (typed locally, no origin label) | v1.7 | v2.0 as first measured | v2.0 now |
|---|---:|---:|---:|
| 20 evasions, written before the change | 11 refused | 20 | 20 |
| 14 benign look-alikes for them | 1 false alarm | 0 | 0 |
| 20 attacks, held out (written after the change, run once) | 13 refused | **15** | 20 |
| 15 benign commands, held out | 1 false alarm | **1** | 0 |

The held-out column in bold is the honest measurement: 15 of 20 refused and 1 false alarm in 15. The
five misses and the false alarm were fixed after that run:
- a zsh `ztcp` socket;
- an awk `/inet/tcp` socket;
- `openssl s_client` piped into `/bin/sh`;
- the system crontab spool;
- gpg with options before `-c`;
- the false alarm: `ssh-keygen -f` naming the key it creates.

All 40 attacks and 29 benign commands are in `tests/test_intent.py`, so they now count as coverage,
not as a measurement. The barrier still sees only command text. A command that hides its intent
inside a script file or a binary shows only what its text shows.
